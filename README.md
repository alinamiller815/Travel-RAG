# AI Guide — Setup

## 🛠️ Требования для локального запуска

- Docker (рекомендуется версия 24+)
- Docker Compose (рекомендуется версия 2+; встроен в Docker Desktop на Windows/macOS)

## 🚀 1. Запуск проекта

Клонировать репозиторий:

```bash
git clone <repo-url>
cd <repo-folder>
```

## 🔑 2. Настройка ключей

Создайте файл .env в корне проекта по образцу .env.example:

```
MISTRAL_API_KEY=your_api_key_here
HF_TOKEN=your_api_key_here
TELEGRAM_BOT_TOKEN=your_api_key_here
RAG_PORT=8001
DATA_DIR=/app/data
API_URL=http://rag-app:8001/answer
```

## ▶️ 3. Запуск сервиса


### 🐳 1. Запуск init-сервиса
```docker compose build init-data docker compose up init-data ```

###  2. Запуск основных сервисов

```docker compose up -d rag-app telegram-bot```


### 🤖 2. Зайти в телеграм бот @TravelRagTestBot (или завести своего бота)
Набрать ```/start```, дождаться ответа от бота и задать свой вопрос.

##  4. Описание docker-compose.yml

Файл `docker-compose.yml` описывает компоновку многоконтейнерного приложения, реализованного с использованием Docker Compose. Проект состоит из трёх сервисов, работающих в связке и объединённых в единую Docker-сеть `rag-network`.

### Сервисы

**init-data**  
Одноразовый init-сервис, предназначенный для начальной инициализации данных (построение индексов для RAG). Образ сервиса автоматически собирается из Dockerfile, расположенного в директории `init-data`. Сервис использует volume `./data` для сохранения результатов работы и volume `./common` для доступа к общему коду. После выполнения команды инициализации контейнер завершается и не перезапускается.

**rag-app**  
Основной application-сервис, представляющий собой backend-приложение на FastAPI, запускаемое через Uvicorn. Образ собирается автоматически из локального Dockerfile. Сервис зависит от успешного завершения `init-data` (используется `depends_on` с условием `service_completed_successfully`), использует volumes для доступа к подготовленным данным и общему коду, а также имеет проброс порта `8001` для доступа к API извне. Для контроля работоспособности сервиса реализован `healthcheck`.

**telegram-bot**  
Дополнительный application-сервис — Telegram-бот, который взаимодействует с `rag-app` через HTTP API. Образ сервиса собирается автоматически из Dockerfile в директории `telegram-bot`. Сервис запускается после старта `rag-app` и использует переменные окружения из файла `.env`.

### Общие настройки

- Все сервисы имеют жёстко заданные имена контейнеров.
- Переменные окружения вынесены в отдельный файл `.env`.
- Используется одна явно заданная Docker-сеть `rag-network`.
- Для сервисов применяются ключи `command`, `depends_on`, `volumes`, `ports` и `healthcheck`, что полностью соответствует требованиям задания.



##  5. Ответы на вопросы
### 1. Можно ли ограничивать ресурсы (например, память или CPU) для сервисов в docker-compose.yml? Если нет, то почему,если да, то как?
Ответ: Да, ресурсы можно ограничивать. В docker-compose есть параметры mem_limit и cpus для обычного режима, а также секция deploy.resources, которая полностью работает в Docker Swarm. В нашем проекте ограничения не использовались, так как это не требовалось заданием.

### 2. Как можно запустить только определенный сервис из docker-compose.yml, не запуская остальные?
Нужно указать имя сервиса при запуске, например ```docker compose up rag-app ```. Можно использовать флаг --no-deps, чтобы отключить зависимости, так как автоматом будут запускаться сервисы, от которых он зависит.
